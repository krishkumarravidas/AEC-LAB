Module 2 — Cloud & Distributed Systems

Exponential Distribution: Cloud Request Inter-Arrival Time

Industry Scenario: A microservice API gateway receives incoming HTTP calls. Modeling request inter-arrival time is critical for provisioning keep-alive connection pools, dynamic horizontal pod autoscaling (HPA), and thread starvation management.

⚠️
Critical Modeling Assumption: This module models request inter-arrival time (the elapsed idle duration between incoming client requests) assuming a constant-rate Poisson arrival process. Do not confuse inter-arrival time with server response latency: response latency measures the backend computation execution time, which typically depends on database queries and system queues.

The Memoryless Property Verified

P(T > t₂ | T > t₁) = P(T > t₂ − t₁)

If the gateway has already waited 4.0s with zero incoming packets, what is the probability it must wait at least another 6.0s (total horizon 10.0s)?

P(T > t₂) / P(T > t₁): 0.3012
P(T > t₂ − t₁) [Fresh 6.0s wait]: 0.3012

Key Insight: The past wait time provides zero information about when the next request will arrive. The system does not "age" or get "due" for a packet.

Cloud Architecture & SRE Implications

  • Connection Keep-Alive: Because idle periods follow a long-tailed exponential survival function, keeping idle TCP sockets open indefinitely exhausts system file descriptors. Set idle timeouts using $P(T > t_{idle}) < \epsilon$.
  • Autoscaler Cooldown: When traffic spikes ($\lambda$ increases), short inter-arrival times cluster naturally. Autoscalers must apply moving average filters or exponential smoothing to avoid continuous thrashing.
  • Rate Limiting / Leaky Bucket: Token-bucket rate limiters buffer bursts caused by Poisson event clustering even when the long-term average $\lambda$ is well within capacity.
